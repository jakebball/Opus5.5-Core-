What one /setup gives a project

Run /setup MyGame with the place open in Studio. It asks what the game is, what it should look like and how animation should feel, then writes all of this. Run it on an existing project and it audits the docs and the live place instead, and offers fixes without overwriting anything.

The asset loop

Each asset is a Python script. Claude writes it, builds it in Blender with no window, reads the rendered sheet, fixes and rebuilds until it reads right, and only then touches Studio. Nothing is uploaded until the user approves.

Script

blender-source/Asset.py

Shapes from Blender modifiers and bmesh ops, colours by name from the palette, sockets and attributes authored in the script.

Build

blend.js build · ≈4 s

Four-view contact sheet, size in studs, triangles per part, warnings for holes, flipped faces and budget.

Paint

paint-only rebuild ≈28 s

For painted styles: one texture per MeshPart, painted by library brushes, baked on the GPU and cached.

Preview

blend.js push

Built as MeshParts in Workspace.BlenderImports. Refuses the wrong place and a running playtest.

Look

/assetshot · ≈15 s for 8 views

Rendered offline from the instances in Studio. Studio's camera never moves.

Approve, then upload

push --upload

Mesh and Image assets, straight into ReplicatedStorage.Assets.Models or the map.

Icon

/itemicon

A transparent, outlined render for shops and inventories, stamped on the model as IconImage.

View · why Blender

Why build in Blender at all

Real modelling tools

Bevel, mirror, array, solidify, boolean, spin and inset replace hundreds of hand-placed vertices in Luau. A crate is a few dozen lines.

Judged before Studio

Every build renders a four-view sheet with geometry checks. Bad meshes are caught in seconds, before anything reaches the place.

The script is the asset

Diffable, reviewable and regenerable. It survives what Studio loses: rolled-back writes, and previews that turn to checkerboards after a restart.

Many sessions at once

Headless means no window and no shared viewport, so several agents build and render in parallel. Ten of Joust Tycoon's castle tiers were built at once, one agent per tier.

A library that compounds

84 painters in two style profiles, Painted Toon and Soft Painted. Painters written for one game are promoted into the library on approval, so the next game starts richer.

What it does not cover

Plain Parts (collision, zones, greybox), UI, VFX, animations, skinned meshes, and art that must stay real Parts for studs. Those keep their usual tools.

View · operating rules

The rules that make it work

Docs wait for approval

A change closes with a two-to-three sentence summary. The docs are written once the user says it works, so nothing wrong gets documented.

Claude never playtests

It makes the change, says what to check and offers a /demo video, the one time it may start a playtest. The user plays.

Never through Studio's camera

Every visual check is an offline render. The camera is shared by every session and the user.

Change the script, not the output

Maps, GUIs, assets and code all have a source on disk. Studio runs what was pushed.

One reference asset, then volume

Settle the style on one approved asset before building a batch.

Parallel agents work to a contract

Agents edit their own files and compile-check. One orchestrator pushes, uploads and rebuilds shared things.

View · install

Install it

  1. Install Blender and ffmpeg, clone the repo and run the installer. It checks Node, git, Claude Code, Blender and ffmpeg, installs the skills, fetches robloxMeshTools, writes the team rules into ~/.claude/CLAUDE.md and smoke-builds a crate. 
    powershell -ExecutionPolicy Bypass -File install.ps1 -ProjectsDir "D:\Roblox"
  2. Install the Studio MCP plugin from its releases page into your Plugins folder, and turn on Allow HTTP Requests in each place.
  3. Register the MCP server with Claude Code. 
    claude mcp add robloxstudio -- npx -y robloxstudio-mcp@latest
  4. Open baseplate/RunnerBaseplate.rbxl in Studio, publish it as a new experience, and set the project up. 
    /setup MyGame

macOS and Linux use ./install.sh --projects ~/Roblox. The JARVIS voice is opt-in with -Persona jarvis.

View · limits

Known limits

  • PlatformTested on Windows only; /demo records with Windows screen capture. The tools are plain Node and Blender, so macOS should work, but nobody has run it there yet.
  • GUIsOffline renders do not draw GUIs. GUI layout is checked by reading sizes through the MCP, and the final look is judged in Play.
  • Studio MCPA third-party plugin whose upstream was archived on 2026-06-06; a maintained fork exists. The tools only need its execute_luau bridge.
